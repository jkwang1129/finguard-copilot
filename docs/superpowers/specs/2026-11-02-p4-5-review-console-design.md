# P4-5 事件、SSE 与审核页面设计

按既定 Phase 4 范围实施，保留 P4-4 未提交改动和历史冻结证据。目标是让 REVIEWER 创建分析、看到可靠状态变化、读取已校验结果、提交受控反馈并返回 Core 作最终决定。

## 事件与一致性

MySQL 新增 V12：analysis_event_cursor / analysis_event。每个分析独立序号，父运行行锁和游标锁序列化追加；新增运行及成功状态变更在原事务中写入事件。回滚不留事件，CAS未命中不追加，重投NOOP不制造新状态。已有运行仅回填一条 SNAPSHOT，不伪造历史过程。

事件只含分析UUID、十进制字符串序号、固定状态/类型、受控错误码、结果可用标志和时间；没有任意JSON、业务事实、模型文本或凭据。状态轨迹表示已有状态机的记录，不表示每个外部步骤已成功；细粒度执行证据仍属 P4-4 Trace。

Redis Pub/Sub仅传UUID唤醒，提交后有界异步发布，发布失败不回滚业务。订阅不阻塞启动，消息丢失或Redis停机时仍定期补读MySQL。默认不开启Redis唤醒，配置 COPILOT_EVENTS_REDIS_ENABLED 后接入；两种模式均验收。

## SSE 与访问边界

GET `/api/copilot/review-analyses/{id}/events`，Authorization头携带Bearer；支持Last-Event-ID。使用fetch读取流，不将JWT放URL。建立连接前验证Core REVIEWER与分析归属、游标范围和容量；发送新批次/心跳前重新授权。运行中撤权或失效发送受控stream-error后关闭，不输出异常正文。

每个进程最多16条连接、每审核员最多4条；每连接60秒、每批最多64条、无唤醒最长1秒补读、15秒心跳。固定线程池，无无界任务队列；实际工作线程退出后释放名额。断开、超时、终态均释放订阅。慢客户端只收到少量有界状态消息，不接收模型流式内容。终态后关闭；重连从持久序号补读，不重新POST分析。

## 页面和数据投影

新增授权 GET `/{id}/view` 投影，复用归属检查，仅在SUCCEEDED显示schema校验后的结果。金额、业务ID、Token及费用用精确十进制字符串；未知费用显示未知，预算占用不解释为实际扣费。只展示受控模型标识和版本指纹，不返回原Prompt或完整运行清单。

React页面：Core账号密码登录（开发代理转发到Core登录API），token仅在内存中；创建/加载分析、状态时间线、证据与引用、成本/限制、反馈AGREE/DISAGREE/UNSURE、打开Core审核台。所有服务端字符串按纯文本渲染；不解析HTML/Markdown，不把模型提供的字符串用作URL。Core入口为部署配置中的固定http(s)地址。

网络失败后的创建重试复用同一Idempotency-Key；切换任务或明确新建才更换key。SSE分片、重复、重连和终态都不重复创建分析。401清除会话及结果，403/404/失败/证据不足分别展示。页面不声称模型已批准最终交易，不显示虚构工具调用。

## 验收边界

MySQL并发/回滚/重投，SSE授权/跨用户/重连/Redis中断，浏览器登录→创建→结果→反馈→Core入口与后端记录对照。真实服务配本地模型替身，不新增付费模型调用。UI演练不是领域专家校准，生产高并发、代理部署及完整恢复在P4-6/Phase6另验。
