## 目标与边界

把已有的只读审核辅助链路变成可评测、可控成本、可追踪、可安全演示的系统。Core 继续负责最终审核决定；Copilot 不调用 Core 写接口，不把模型建议当作业务决定。Phase 5 的模型 Tool Calling、持久化 Graph、HITL 和 MCP 不在本阶段实现。LangGraph 只作离线对照基线。

2026-11-02 按用户要求交付 10 例 AI 模拟审核的填写理由与冻结 Judge 结果复算，见[模拟校准收尾](acceptance/2026-11-02-p4-2-simulated-calibration-closeout.md)。本项作为模拟流程完成记录，不改写“真实人工标签”退出条件，也不替代生产质量验收。

1. **先守住质量边界。** H03 是历史已见的 18 位小数压力案例。先写确定性数值校验和拒绝路径，再调整 Prompt 或模型；调优后另建未见保留集。不能把结构、事实复制和引用正确率当作建议正确率。
2. **先定版本，再做报告与 Trace。** 每次运行应能关联事实快照、Prompt、模型、已发布索引和价格表版本；新增数据库字段只通过后续 Flyway migration 增加，不改 V1–V6。
3. **预算和路由不突破 Phase 3 的调用占用语义。** 当前每个分析已有持久化模型调用占用，目标是避免重复供应商请求。Phase 4 可在调用前选择候选模型；在没有经过相同安全/质量评测的备用模型前，不启用自动备用。请求结果不确定时不向另一供应商重试。未来若要同一分析多次调用，必须先单独重设计占用、幂等、账本和恢复契约。
4. **MySQL 是事件真相，Redis 只负责短期控制与唤醒。** SSE 进度从持久事件补读；Pub/Sub 消息丢失不应丢进度。Redis 故障时配额和并发控制采取保守策略，不放开真实模型调用。
5. **评测与生产路径分开。** Python/LangGraph 消费共享的脱敏案例和输出契约，不复制 Core 数据获取或 Java Worker；Judge 结论必须与规则和人工抽样一起报告。
6. **页面只消费经服务端验证的数据。** SSE 只发阶段、序号、受控错误码和最终结果可用通知；页面通过已有 GET 接口取最终结果，不展示流式原文、JWT 或完整 Prompt。

## 工作包验收方法

- 每包先写可失败的契约/故障测试，再实现，最后跑相关集成测试；大包结束跑 `scripts/verify.ps1`。
- 真实供应商测试需单独冻结数据、参数、调用上限和成本预算；普通 CI 与本地全套测试仍不要求密钥、外网或付费调用。
- 对“不能输出方向性建议”的失败路径，检查 API 响应、分析终态、用量账本、Outbox/Worker 回执和 Core 只读状态，而不只检查页面文案。
- 每次关闭工作包保留验收记录和已知限制；不以 `202 Accepted` 代替分析完成。
