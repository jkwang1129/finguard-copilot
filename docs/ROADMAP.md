# FinGuard Copilot 实施路线图

路线按可验收能力递增，而不是按技术名词堆叠。每一阶段必须保留可重复的测试和运行证据，
通过后才进入下一阶段。

阶段 0–3 构成可用 AI MVP；阶段 0–6 构成完整学习与作品路线。阶段 5 的 Agent 能力不
改变 MVP 的只读安全边界，阶段 6 的部署验收覆盖当时已经完成的全部能力。

## 阶段 0：架构基线与工程初始化

交付：

- 范围、架构、ADR 和任务基线；
- Java 17 Spring Boot 工程；
- 分层包结构、统一错误响应、OpenAPI 和配置校验；
- MySQL/Flyway、Testcontainers、CI 和秘密扫描；
- 确定性 Stub 模型与内存检索端口；
- Java 生产服务、Python 评测工具和 React 演示页面的目录与依赖边界。

验收：无模型密钥、无互联网时可以构建和运行全部普通测试；仓库中没有秘密或浮动依赖。

## 阶段 1：只读事实闭环

交付：

- Core `/api/auth/me` 和审核上下文契约；
- Copilot 身份代理、JWT 短暂转发和 `REVIEWER` 校验；
- 分析创建、状态查询、幂等和脱敏事实快照；
- MySQL 事务 Outbox、RabbitMQ、幂等 Worker 和可靠重试；
- Stub 模型结构化分析；
- Schema 与事实一致性校验。

验收：真实 Core 数据可产生完全可追溯的 Stub 分析；401、403、404、409、超时和 Core
不可用均有契约测试；RabbitMQ 短暂不可用时已接受运行不会丢失；不存在业务写调用。

## 阶段 2：RAG 与知识数据管道

交付：

- 文档登记、解析、切分、去重、Embedding 和 Qdrant 适配器；
- 候选索引、评测、发布、增量更新、删除和回滚；
- 检索引用与输出引用校验；
- 固定 RAG 评测集。

验收：每条制度结论都有有效引用；删除或更新文档后旧片段不会继续从已发布版本召回；
索引发布失败可回滚。

## 阶段 3：真实模型与上下文工程

交付：

- 真实模型适配器和配置版本；
- 上下文预算、事实优先、文档裁剪和调用上限；
- Golden Dataset 与模型选型报告；
- 至少两个真实候选模型和离线 Stub 的明确选择；
- Token、延迟、结构化成功率、拒绝判断与成本指标。

验收：候选模型在同一数据集上完成事实正确率、引用准确率、JSON 成功率、注入抵抗、
P50/P95 延迟和成本比较；选型有证据，不以流行度决定。

## 阶段 4：AI 工程化与安全

交付：

- Prompt、模型、索引和价格表版本管理；
- Python 3.12/uv/pytest/Pydantic/Pandas 离线评测工具；
- 共享 Tool Schema 和 Golden Dataset 的 LangGraph 参考基线；
- 规则检查、LLM-as-Judge、人工抽样校准与 Bad Case 报告；
- OpenTelemetry、Langfuse、Prometheus 和 Grafana；
- 受预算约束的多模型路由、Redis 配额和供应商并发控制；
- MySQL 可恢复事件序列、Redis 唤醒、受控 SSE 与 React/TypeScript 轻量演示页面；
- 分析反馈与离线评测报告；
- 输入注入、恶意文档、越权和秘密泄露测试；
- 调用预算、限流、超时、受限重试和安全降级。

验收：所有失败模式不会产生未经验证的方向性建议；Judge 在固定人工样本上有一致率记录；
指标无高基数或敏感标签；给定运行可定位输入、Prompt、模型和索引版本；页面可展示受控
进度、Tool Trace、引用、成本和安全降级。

## 阶段 5：Agent Workflow 与 Tool Use

只有前四阶段稳定后才进入本阶段。

交付顺序：

1. 服务器确定性调用多个 Core 只读端点；
2. 模型从白名单中选择只读工具，服务器校验名称、参数、权限和次数；
3. 用 Graph 表达真实的检索不足重试、输出修复、人工暂停/恢复和失败分支；
4. 使用持久化 Checkpoint 保存运行级 Working Memory；
5. 将已验证的只读能力暴露为 MCP Server；
6. 工具执行后回查事实、回放轨迹并记录审计。

验收：模型不能构造任意工具或 URL；最多两次模型调用、四次工具调用；预算、权限和
状态恢复均有测试；RabbitMQ 重投不会重复执行工具；HITL 恢复会复查权限和过期状态。
业务写工具仍不属于默认范围。

## 阶段 6：production-like 部署

交付：

- Java、React 和 Langfuse 所需的非 root 镜像及 Compose 开发/集成环境；
- CI 测试、镜像检查、秘密扫描和完整 Git SHA 标签；
- Linux 部署与回滚脚本；
- MySQL 备份恢复、RabbitMQ/Outbox 恢复、Qdrant 索引重建；
- Core、数据库、消息队列、Redis、向量库、遥测和模型提供商故障演练；
- 部署、回滚、故障和验收报告。

验收：可以从空环境部署、运行真实审核演示、执行故障降级、恢复数据与索引、回滚到前一
版本并清理所有本次资源。文档统一称为 production-like，而非真实金融生产环境。
