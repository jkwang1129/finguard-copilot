## 数据与评分修复

- 原 `phase3-golden-v1` 保留不变。其六案例缺少输出必需的交易及账户 ID，三个案例的期望路径超出当前六路径白名单；金额、频率案例也未提供可独立判断的完整阈值依据。
- 新增 `phase3-quality-v2`，保留六类业务案例和原推荐标签，补齐合成 ID、明确阈值与政策依据；不通过降低期望标签或放宽 Java 校验提分。
- 新版路径覆盖率只衡量当前契约支持的六个字段。频率与对账事实仍在输入中，但不再作为该输出字段无法承载的期望路径；这些额外事实及自然语言推理尚无独立完整性评分。
- 出网前预检整批案例，拒绝缺失事实、非法金额、重复案例及不可表示的期望路径，避免浪费额度。
- 两组均生成相同的确定性 analysisId 和可复制的引用 JSON，不把期望答案或评分字段放进请求。
- 本次真实报告由 `exact-facts-citations-v2` 生成，校验六个事实值、analysisId、路径白名单及引用的文档/版本/章节/完整原文；语义校验失败不计有效建议，并保留 Token 用量。v2 的浮点解析精度存在限制，见复查说明。

因此，不应将历史千问的 19.4% 与本轮 100% 相减作为“模型提升”：模型、数据和评分标准都已变化。可比收益仅是本轮 DeepSeek 上 v1 与 v2 的同条件对照。

## 复查修复与证据版本

独立只读复查发现三项问题，均先用离线失败测试复现，再修复：

1. 推荐值为数组或对象时，集合判断抛异常而中断整批；现在记录 `INVALID_SCHEMA`、保留用量并继续处理剩余案例。
2. 先用浮点解析再转 Decimal 会掩盖金额差异，例如 `12500.0000000000001` 被舍入为 `12500`。现在从 JSON 解析阶段保留 Decimal 精度，并覆盖大金额分位差异回归。
3. 旧单模型入口在载入本地 provider 前就计算默认文件名；现在先加载环境，再生成含 provider、时间和随机标识的路径，已有报告一律拒绝覆盖。默认改用新版案例及提示词，保留显式参数选择旧版本。

修复后的真实评测版本为 `exact-facts-citations-v3`。上表及归档 JSON 仍保留实际运行时的 v2 标签，没有改写成 v3 结果。未保存模型原始 JSON，无法用 v3 离线重放这 12 次响应；因此，不能把 v2 的事实值 100% 当作 v3 严格十进制校验的真实模型证据。v3 当前只有离线回归证据；12 次调用预算已用完，没有追加 API 请求。引用覆盖率的比较仍按原报告保留，不将其扩展为全面质量结论。
