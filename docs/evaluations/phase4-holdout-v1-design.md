# Phase 4 未见保留集设计草案

状态：合成单规则 v1 已冻结，数据及隔离边界见[冻结清单](phase4-holdout-v1-freeze.md)。本文件定义更完整的质量保留集设计；当前 v1 未覆盖真实注入载荷、政策冲突或多条件，不证明生产质量。

## 目标与边界

用新的合成案例检查确定性规则、证据缺失、建议与证据的关系和已知安全类别。正式案例不得由接触本会话中具体规则实现、Phase 3 结果或护栏测试细节的上下文编写；由独立作者仅依据对外公开的数据契约和业务规则语义创建。隔离应记录输入材料与可见性，未经独立性确认的案例只能作为开发集。

不采集个人信息、真实交易、密钥、JWT、完整真实 Prompt 或生产知识。项目内演示政策不等于真实金融政策；标签由谁审核、是否为领域专家必须明确记录。

## 类别矩阵

正式案例至少包含：规则适用与不适用、等值/边界两侧、缺失或冲突事实、币种不一致、多条件及豁免、引用缺失或版本不匹配、应拒答、用户输入与知识来源的指令攻击、普通无攻击对照。攻击样例只证明所测样本，不能支持通用防护结论。

每例需有唯一非敏感 case ID、合成事实、版本化政策证据、预期受控建议或预期拒绝、理由来源、必要事实路径与引用目标。最终数量与各类别配额在独立编写前冻结；案例与标签核对不得泄漏到调优或提示词修改中。多标签类别须明确主类别与分母，错误和缺失不能从统计中剔除。

## 冻结和使用

1. 隔离作者完成案例与标签后，记录隔离范围、生成方式、审核者和冲突处理；以独立脚本核验唯一性、字段、引用与数值格式。
2. 冻结完整数据文件、设计文件及相关验证代码的 SHA-256，记录数据版本、样本数、类别计数、审定状态；不得覆盖 Phase 3 文件。
3. 冻结后进行正式模型评测前，固定 Prompt、模型、索引、规则、预算和运行 ID；结果及异常均保留，禁止根据结果修改同版本数据。
4. 对数据泄漏、事实矛盾或标签错误，停止把该集称为未见集；修订为新版本并重新冻结。真实供应商调用须单独批准预算和调用上限。
